# มาตรฐานโค้ดก่อนขึ้น Production

มาตรฐานการเขียนโค้ด 11 ข้อสำหรับทีม พร้อม **หลักฐานว่าแต่ละข้อสำคัญจริง** — ไม่ใช่หลักการลอย ๆ
ทุกข้อมีโค้ดจริงประกอบ มาจากการทดลองให้เขียนงานเดียวกันสองเวอร์ชันคู่ขนาน
เวอร์ชันหนึ่งมีมาตรฐานชุดนี้กำกับ อีกเวอร์ชันไม่มี แล้วให้ผู้ตรวจอิสระให้คะแนนโดยไม่รู้ว่าอันไหนเป็นอันไหน

## เริ่มตรงไหน

| ถ้าคุณคือ | อ่าน |
| --- | --- |
| คนในทีมที่จะเขียนโค้ด | [`docs/index.html`](docs/index.html) — เอกสารหลัก 11 ข้อ + checklist ก่อนเปิด PR |
| คนที่อยากให้ Claude Code บังคับมาตรฐานนี้ให้อัตโนมัติ | [`skill/principal-engineer/`](skill/principal-engineer/) |
| คนที่ไม่เชื่อว่ามันต่างกันจริง | [`evidence/`](evidence/) — โค้ดดิบทั้งหมดของทั้งสองฝั่ง + ผลตรวจ |

## ผลการทดลองโดยย่อ

| โจทย์ | มีมาตรฐาน | ไม่มี | หลังแก้ (รอบ 2) |
| --- | ---: | ---: | ---: |
| Refactor route ที่รก (94 บรรทัด ฝังปัญหาไว้) | 11/11 | 10/11 | 14/14 |
| Payment webhook (Node + TypeScript) | 10/10 | 8/10 | 15/15 |
| Report script (Python + PostgreSQL → CSV) | 8/9 | 8/9 | 14/14 |
| **รวม** | **96.3%**<br>(30 เกณฑ์) | **86.7%**<br>(30 เกณฑ์) | **100%**<br>(43 เกณฑ์) |

ตัวเลขนี้ **บอกทิศทาง ไม่ใช่ค่าที่แม่นยำ** — รันฝั่งละรอบเดียว และ 14 จาก 30 เกณฑ์ผ่านทั้งสองฝั่ง
เรื่องที่ต่างกันจริงกลับเป็นเรื่องที่ไม่มีเกณฑ์ข้อไหนตรวจเลย ผู้ตรวจไปเจอเองระหว่างอ่านโค้ด:

- ฝั่งที่ไม่มีมาตรฐาน **เปลี่ยนกติกาธุรกิจเงียบ ๆ** ตอน refactor (`total > 1500` → `>=` = เสียค่าส่ง 60 บาทต่อออเดอร์ที่ยอดตรงเกณฑ์) แล้วเขียน test ล็อกค่าใหม่ไว้ด้วย
- ฝั่งที่ไม่มีมาตรฐาน สร้าง **DI container + 4 class ที่มี implementation เดียว** ทำให้ flow เดียวกระจายไป 4 ไฟล์
- ฝั่งที่ไม่มีมาตรฐาน ส่ง webhook service ที่ต่อ **in-memory repository เข้า production entrypoint** — deploy แล้ว webhook จริงจะ 404 ทุกใบ
- ฝั่งที่ไม่มีมาตรฐาน **พิมพ์ค่า secret จริงซ้ำลงเอกสารสรุป** ขณะกำลังเขียนอธิบายว่าต้อง rotate

## ข้อที่มาตรฐานชุดนี้เองเคยทำได้ไม่ดี — และผลหลังแก้

เขียนไว้ให้เห็นด้วย เพราะคู่มือที่มีแต่ข้อดีของตัวเองไม่มีใครเชื่อ

รอบแรกเจอสองข้อที่ **มาตรฐานชุดนี้ทำให้แย่ลงกว่าไม่มีเลย** แก้แล้วและรันโจทย์เดิมซ้ำเพื่อพิสูจน์:

| ปัญหา | รอบแรก | รอบสอง (หลังแก้) |
| --- | --- | --- |
| สร้างของเกินโจทย์ (โจทย์ขอ "script") | 18 ไฟล์ · 1,125 บรรทัด | **4 ไฟล์ · 400 บรรทัด** |
| รายงานตัวเลข test เกินจริง | อ้าง "25/25, 9/9, 3/3" ทั้งที่ vitest รันไม่ได้ | **"ไม่มีตัวเลขผ่าน/ไม่ผ่านให้"** |

รอบสองผ่านเกณฑ์ **43/43** (เพิ่มจาก 30 เป็น 43 ข้อ ตามที่ผู้ตรวจรอบแรกติมาว่ายังไม่มีใครตรวจ)
และตัวเลข test ที่รายงานมาถูกรันซ้ำยืนยันแล้วทั้งสองเคส

⚠️ **43/43 เทียบกับ 96.3% ของรอบแรกตรง ๆ ไม่ได้** — คนละชุดเกณฑ์ รอบสองเข้มกว่าแต่ตัวเลขรวมไม่ได้บอกแบบนั้น

### ที่ยังค้างอยู่

รอบสองเจอของใหม่: มันโชว์ตัวอย่าง CSV ที่แต่งขึ้นเอง โดยเลขขัดกับสูตรของสคริปต์ตัวเอง
(`1284530 / 412 = 3117.79` แต่ในตารางเขียน `3116.58`) รากปัญหาเดียวกับเรื่องตัวเลข test
เพิ่มกติกาลงมาตรฐานแล้ว แต่ **ยังไม่ได้ทดสอบว่าได้ผล** — รอ iteration 3
