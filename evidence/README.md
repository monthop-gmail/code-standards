# หลักฐาน

โค้ดดิบทั้งหมดจากการทดลอง เปิดดูเทียบกันเองได้

## วิธีทดลอง

โจทย์เดียวกันถูกส่งให้สองเวอร์ชันพร้อมกัน:

- **with_skill** — มี `skill/principal-engineer/` กำกับ
- **without_skill** — ไม่มีอะไรเลย ถูกสั่งห้ามอ่าน skill ใด ๆ

ทั้งสองฝั่งถูกห้าม `npm install` / `pip install` และห้ามต่อ database จริง
จากนั้นผู้ตรวจอิสระอ่านผลลัพธ์แบบไม่รู้ว่าฝั่งไหนเป็นฝั่งไหน (เรียกว่า A/B) แล้วให้คะแนนตามเกณฑ์ที่เขียนไว้ล่วงหน้าใน `evals/evals.json`

## อ่านผลตรงไหน

| ไฟล์ | คืออะไร |
| --- | --- |
| `iteration-1/benchmark.md` | สรุปคะแนน เวลา token |
| `iteration-1/benchmark.json` | มี `notes[]` — ข้อสังเกตที่ตัวเลขรวมกลบไว้ |
| `iteration-1/<โจทย์>/eval_metadata.json` | โจทย์ + เกณฑ์ตรวจของเคสนั้น |
| `iteration-1/<โจทย์>/<ฝั่ง>/grading.json` | ผ่าน/ไม่ผ่านรายข้อ พร้อมอ้าง file:line |
| `iteration-1/<โจทย์>/<ฝั่ง>/outputs/RESPONSE.md` | ข้อความที่แต่ละฝั่งจะตอบผู้ใช้จริง |
| `iteration-1/<โจทย์>/<ฝั่ง>/static_checks.json` | ผลสแกน regex (หลักฐานดิบ ไม่ใช่คำตัดสิน) |
| `review-iteration-1.html` | หน้าเทียบผลแบบกดดูทีละเคส เปิดในเบราว์เซอร์ |

`run-1/` ในแต่ละฝั่งเป็นสำเนาของ `grading.json` + `timing.json` ที่สคริปต์รวมคะแนนต้องการตามโครงที่มันคาดหวัง — ไม่ใช่การรันรอบที่สอง

## ชุดเกณฑ์ตรวจ

`evals/evals.json` คือชุดกลางที่ใช้กับรอบถัดไป ปัจจุบันเป็น **v2 · 43 เกณฑ์**

| เวอร์ชัน | จำนวน | เปลี่ยนอะไร |
| --- | ---: | --- |
| v1 (iteration 1) | 30 | ชุดแรก |
| v2 (หลัง iteration 2) | 43 | เพิ่ม 13 ข้อตามที่ผู้ตรวจรอบแรกบอกว่ายังไม่มีใครตรวจ และแก้ถ้อยคำ 3 ข้อที่มีปัญหา |

ถ้อยคำที่แก้ใน v2:

- **eval-0 ข้อ 12/13 เคยขัดกันเอง** — ข้อ 12 เขียนว่า "รักษาพฤติกรรมเดิมทุกกติกา" แบบสัมบูรณ์ ทำให้ข้อ 13 (ต้องบอกเมื่อเปลี่ยนกติกา) ไม่มีทางถูกใช้ และลงโทษการแก้ช่องโหว่ที่จำเป็น v2 จำกัดข้อ 12 ไว้ที่ผลลัพธ์ของการคิดราคาเท่านั้น แล้วให้ข้อ 13 รับผิดชอบการเปลี่ยนแปลงอื่นทั้งหมดพร้อมเงื่อนไขไม่ผ่านที่ชัดเจน
- **eval-1 ข้อ 9 เคยอ่อนเกินไป** — "ไม่มี TODO / placeholder" ผ่านได้ด้วยการเลี่ยงคำว่า TODO เฉย ๆ แม้ logic จะยัง stub อยู่ v2 เปลี่ยนเป็นตรวจว่าทุกเส้นทางที่ endpoint เรียกไปจบที่โค้ดที่ทำงานจริง และระบุวิธีตรวจไว้ในตัวเกณฑ์ว่าให้ไล่ call chain ไม่ใช่ grep

`grading.json` กับ `assertions[]` ใน `eval_metadata.json` ของแต่ละรอบ **ไม่ถูกแก้ย้อนหลัง**
เพราะเป็นบันทึกว่าตอนนั้นตรวจด้วยเกณฑ์อะไร รายละเอียดปัญหาของแต่ละข้ออยู่ใน `eval_metadata.json` ฟิลด์ `assertion_issues`

## ข้อจำกัด

- 3 โจทย์ ฝั่งละ 1 รอบ ไม่ได้วัดความผันผวน
- 14 จาก 30 เกณฑ์ผ่านทั้งสองฝั่ง = แยกฝีมือไม่ได้
- เกณฑ์ v1 ไม่ครอบคลุมเรื่องที่ต่างกันจริง (behaviour preservation, ความพอดีของขนาดงาน) — ผู้ตรวจไปเจอเอง แก้แล้วใน v2
- v2 ยังไม่มีเกณฑ์ตรวจการแต่งตัวอย่าง output (เช่น CSV สมมติที่เลขขัดกับสูตรของตัวเอง) ซึ่งผู้ตรวจรอบสองจับได้
