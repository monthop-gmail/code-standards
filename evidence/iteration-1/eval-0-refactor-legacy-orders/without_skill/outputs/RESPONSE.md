## ช่องโหว่ที่เจอ

**SQL injection ทุกจุดที่แตะ database** — ทั้ง 7 query ต่อ string ตรง ๆ จาก request เช่น

```js
await pool.query("SELECT * FROM coupons WHERE code = '" + coupon + "'");
```

ยิง `{"coupon": "' OR '1'='1"}` เข้าไปก็อ่านตารางอื่นได้ หรือส่ง `productId` เป็น subquery ก็ดึงข้อมูลออกได้ทั้งฐาน ตอนนี้เปลี่ยนเป็น parameterized query หมดแล้ว บวก validate ชนิดข้อมูลตั้งแต่ขาเข้า

**ไม่มีการตรวจสิทธิ์เลย** — `userId` เชื่อจาก request body ตรง ๆ แปลว่าสั่งของในนามคนอื่นได้ และ `GET /orders/:id` เดา id เอาก็อ่านออเดอร์ชาวบ้านได้หมด ผมใส่ ownership check ไว้ให้แล้ว แต่มันจะทำงานก็ต่อเมื่อมี auth middleware เซ็ต `req.user` — ตรงนี้ผมไม่รู้ว่าระบบคุณใช้อะไรอยู่ เลยเว้นจุดต่อไว้ใน `src/app.js` ครับ **ถ้ายังไม่เสียบ auth ช่องโหว่นี้ยังเปิดอยู่**

**log ข้อมูลลูกค้า** — `console.log('order created', orderId, req.body)` เขียนอีเมลและตะกร้าทั้งใบลง stdout ซึ่งมักไหลไป log aggregator ต่อ เปลี่ยนเป็น structured log ที่เลือก field เองแล้ว

## บั๊กที่แก้ไปด้วย

**เงินหายเพราะ transaction ไม่มี** — ของเดิม insert `orders` แล้วค่อยวน insert `order_items` ทีละแถวแบบ autocommit ถ้าพังกลางทางจะเหลือออเดอร์ที่มีของไม่ครบค้างใน DB ตอนนี้ห่อใน transaction เดียว พังเมื่อไหร่ rollback ทั้งก้อน

**คำนวณเงินด้วย float** — `price * 0.95 * 0.9` สะสมความคลาดเคลื่อนแล้วเขียนลง DB ตรง ๆ เปลี่ยนมาคิดด้วยจำนวนเต็มหน่วยสตางค์ทั้งหมด ปัดเศษตรงจุดที่ตั้งใจปัดเท่านั้น

**ยอดติดลบได้** — คูปองแบบ fixed ที่มากกว่าราคาของ ทำให้ `total` ติดลบแล้วบันทึกลงฐานเลย ตอนนี้ตัดที่ศูนย์

**คูปองผิดแต่เงียบ** — ของเดิมถ้าหาโค้ดไม่เจอจะข้ามไปเฉย ๆ ลูกค้าพิมพ์โค้ดผิดจะไม่รู้ตัวจนโดนตัดเงินเต็ม แถมไม่เช็ควันหมดอายุด้วย ตอนนี้เช็ค `expires_at` ใน SQL และตอบ 400 กลับไปถ้าโค้ดใช้ไม่ได้

**สินค้าไม่มีจริงแล้ว crash** — `rows[0].price` ตอน query ไม่เจอจะได้ TypeError แล้วตกไปที่ catch กลายเป็น `{ok:false}` ตอนนี้ตอบ 400 พร้อมบอกว่า product ไหน

**`GET /orders/:id` ไม่มี try/catch** — DB error กลายเป็น unhandled rejection ลูกค้าค้างรอจน timeout

**status code ผิดหมด** — ทุก error ตอบ HTTP 200 พร้อม `{ok:false}` ทำให้ monitoring แยกไม่ออกว่า input ผิดหรือ DB ล่ม ตอนนี้ 400/403/404/422/500 ตามเหตุ

**N+1 query** — ตะกร้า 20 ชิ้นยิง 20 query ตอนนี้เหลือ query เดียวด้วย `IN (...)` เหมือนกันกับตอนอ่านชื่อสินค้าใน `GET`

**dead code** — `if (total > 1500) { total = total }` ไม่ทำอะไรเลย เจตนาจริงคือส่งฟรีเมื่อยอดถึงเกณฑ์ ผมเขียนตามเจตนานั้น ถ้าตีความผิดบอกได้ครับ

## โครงสร้างใหม่

แตกจากไฟล์เดียว 94 บรรทัดเป็น layer ตามหน้าที่:

```
src/
  domain/pricing.js       ← กฎราคาล้วน ๆ ไม่แตะ DB ไม่แตะ HTTP
  domain/money.js         ← คิดเงินด้วยจำนวนเต็ม
  repositories/           ← SQL ทั้งหมดอยู่ที่นี่ parameterized หมด
  services/orderService.js← ลำดับงาน: คิดราคา → บันทึก → ส่งเมล
  http/routes/orders.js   ← เหลือแค่แปลง HTTP ↔ service
  http/validators/        ← ตรวจ input ขาเข้า
```

หัวใจคือ `domain/pricing.js` เป็น pure function ทั้งหมด ตรรกะธุรกิจที่สำคัญที่สุดเลยเทสได้โดยไม่ต้องมี DB และ router เปลี่ยนเป็น factory ที่รับ dependency เข้ามา — ของเดิมพอ `require` ไฟล์ก็เปิด connection ไป production ทันที ซึ่งเป็นเหตุผลที่มันเทสไม่ได้เลย

ตัวเลขเวทมนตร์ (`10`, `0.95`, `3`, `0.9`, `1500`, `60`) ตั้งชื่อไว้ใน `PRICING_RULES` ที่เดียวแล้ว

## ที่ต้องทำต่อ

1. **rotate credential ทั้งสองตัว** — ข้อนี้สำคัญสุด
2. เสียบ auth middleware ให้ `req.user` มีค่า ไม่งั้น ownership check ไม่ทำงาน
3. ตาราง `coupons` ต้องมีคอลัมน์ `expires_at` (ผม query ถึงมัน) ถ้า schema ยังไม่มีต้อง migrate ก่อน
4. ยังไม่ได้แตะเรื่อง **ตัดสต็อก** — โค้ดเดิมไม่เคยเช็คว่าของพอไหมและไม่เคยหักสต็อก สั่งเกินจำนวนที่มีได้ อันนี้เป็น feature ที่หายไปไม่ใช่บั๊ก เลยไม่กล้าใส่เอง บอกได้ถ้าอยากให้ทำ
5. ของเดิมไม่มี idempotency ลูกค้ากดสั่งซ้ำได้ออเดอร์ซ้ำ

ไฟล์เดิมผมไม่ได้แตะนะครับ ของใหม่อยู่ใน `outputs/` ทั้งหมด
