ไฟล์นี้ไม่ได้แค่รก — มันมี SQL injection ทุก query, รหัสผ่าน production กับ API key ฝังอยู่ในโค้ด, และใครก็สั่งของในนามคนอื่นหรืออ่านออเดอร์ชาวบ้านได้ ผมแยกโครงและแก้ทั้งชุดให้แล้ว

## แผนที่ใช้

1. แยกตามเหตุผลของการเปลี่ยนแปลง: กติกาคิดเงิน (ฝ่ายธุรกิจแก้) / SQL (schema แก้) / HTTP (contract แก้) — สามอย่างนี้เดิมพันกันอยู่ในฟังก์ชันเดียว 68 บรรทัด
2. ปิดช่องความปลอดภัยทั้งหมดในรอบเดียว: parameterized query, secret ไป env, ตัวตนผู้ใช้มาจาก session ไม่ใช่ body, GET ผูกเจ้าของ
3. แก้ correctness ที่ทำให้เสียเงิน: N+1, ไม่มี transaction, คิดเงินด้วย float
4. คงกติกาธุรกิจเดิมทุกข้อ ยกเว้นที่ระบุไว้ในหัวข้อ "พฤติกรรมที่เปลี่ยน" ข้างล่าง

`src/orders/routes.js` ใช้แทน `legacy_orders.js` ได้ตรง ๆ — path ที่ประกาศยังเป็น `/orders` กับ `/orders/:id` เหมือนเดิม จุด mount ไม่ต้องแก้

เหตุผลที่แยกแค่นี้ ไม่มากกว่านี้: `pricing.js` แยกเพราะเป็นส่วนที่ผิดแล้วเสียเงินจริงและต้อง test ได้โดยไม่ต้องมี DB, `repository.js` แยกเพราะ SQL ควรอยู่ที่เดียวให้ตรวจได้ว่า parameterized ครบ ส่วนที่เหลือไม่มี interface/factory/DI container เพราะมี implementation เดียวและยังไม่มีอะไรให้สลับ

## แก้อะไรไปบ้าง

**Security**
- SQL injection 6 จุด → parameterized ทั้งหมด (เดิม `WHERE code = '" + coupon + "'` และ `WHERE id = " + req.params.id` เปิดโล่ง)
- credential ทั้งหมดย้ายไป env และ fail ตั้งแต่ boot ถ้าไม่ครบ
- `req.body.userId` ถูกทิ้ง — ตัวตนมาจาก `req.user.id` ที่ auth middleware ใส่ให้เท่านั้น
- `GET /orders/:id` เดิมไม่เช็คเจ้าของเลย ตอนนี้เงื่อนไข `user_id = ?` อยู่ใน SQL ออเดอร์คนอื่นจึงให้ผลเหมือนไม่มีอยู่จริง ไม่รั่วว่า id ไหนถูกใช้แล้ว
- `console.log('order created', orderId, req.body)` log ทั้ง body รวมอีเมลลูกค้า → เหลือ log แบบมีโครงสร้างที่ไม่มี PII

**Correctness**
- N+1 หายไป: สินค้าดึงด้วย query เดียว (`IN (?)`), รายการในออเดอร์ใช้ JOIN, order_items insert ทีเดียวทั้งชุด — จากเดิม 1 + 2n queries
- order กับ order_items อยู่ใน transaction เดียว เดิมถ้า insert แถวกลางพัง จะเหลือ order ที่มีของไม่ครบค้างใน production
- คิดเงินด้วยจำนวนเต็มหน่วยสตางค์ทั้งหมด (`0.95 * 0.9` บน float ทำยอดเพี้ยนแล้วสะสมข้ามบรรทัด) เก็บลง DB ยังเป็น DECIMAL หน่วยบาทเหมือนเดิม **ไม่ต้อง migrate**
- `if (total > 1500) { total = total }` — บรรทัดที่ไม่ทำอะไรเลย ตอนนี้เป็น `shippingMinor = ... ? 0 : SHIPPING_FEE_MINOR` ที่อ่านออกว่าแปลว่าส่งฟรี
- สินค้าไม่มีอยู่จริง เดิมพังเป็น TypeError; สินค้าถูกลบหลังสั่ง เดิมทำ `GET` พังทั้ง request — ทั้งสองเคสตอบให้ถูกแล้ว
- `catch (e) {}` ของการส่งเมลหายไป ทุกความล้มเหลวถูก log พร้อม orderId และมี timeout 5 วินาที (เดิมไม่มี timeout เลย ผู้ให้บริการเมลค้างเมื่อไหร่ ลูกค้าค้างด้วย)
- `catch` ตัวนอกที่ตอบ `{ok:false}` HTTP 200 ทุกกรณี → error middleware ที่ตอบ status จริงและไม่ปล่อย stack trace ออกไป
- `var` + index loop → `const`/`map`/`reduce`, ไม่มี floating promise เหลือ

## พฤติกรรมที่เปลี่ยน — ต้องรู้ก่อนขึ้น

1. **ต้องมี auth middleware** ที่ตั้ง `req.user.id` mount ไว้ก่อน router นี้ ถ้าตอนนี้ยังไม่มี ทั้งสอง endpoint จะตอบ 401 ทันที — นี่คือราคาของการปิดช่องที่ให้ client บอกเองว่าตัวเองเป็นใคร ถ้าระบบยังไม่มี auth เลย บอกผมได้ว่าใช้อะไรอยู่ (session, JWT) เดี๋ยวต่อให้
2. **คูปองที่ไม่มีในระบบ ตอบ 422 แทนการเงียบ** เดิมพิมพ์โค้ดผิดแล้วระบบคิดเต็มราคาให้เฉย ๆ ลูกค้าเพิ่งมารู้ตอนเห็นใบเสร็จ ถ้าอยากได้พฤติกรรมเดิม แก้ที่ `service.js` ให้ข้ามการ throw `UNKNOWN_COUPON`
3. **HTTP status ถูกต้องแล้ว**: 201 ตอนสร้างสำเร็จ, 400 input ผิด, 401 ไม่ได้ล็อกอิน, 404 ไม่พบ, 422 สินค้า/คูปองไม่มีจริง, 500 ที่เหลือ — client ที่เช็คแค่ `body.ok` ยังใช้ได้ (รูป response ตอนสำเร็จเหมือนเดิม) แต่ตัวที่สมมติว่า status เป็น 200 เสมอจะเจอของใหม่
4. **body ของ error** เป็น `{ ok: false, error: { code, message, details? } }` จากเดิม `{ ok: false }` เปล่า
5. **คูปองดันยอดติดลบไม่ได้แล้ว** เดิมคูปองลด 500 บนตะกร้า 300 ได้ยอด -140 บาท ตอนนี้หยุดที่ 0 แล้วบวกค่าส่ง
6. **ยอดอาจต่างจากเดิมได้ไม่เกิน 1 สตางค์ต่อหน่วย** เพราะปัดเศษที่ราคาต่อหน่วยก่อนคูณจำนวน (ราคานี้คือค่าที่เก็บลง `order_items.unit_price` จริง จึงควรเป็นค่าที่ปัดแล้ว)

**ที่ตั้งใจไม่แตะ**: อัตราส่วนลดและลำดับการคิดทบ (>10 ชิ้นลด 5% แล้วค่อยหมวด 3 ลด 10% = 85.5%), การคิดค่าส่งจากยอด*หลัง*หักคูปอง (คูปองทำให้หลุดเกณฑ์ส่งฟรีได้ — เป็นของเดิม ผมคงไว้), และ coupon type ที่ไม่ใช่ `percent` ถือเป็นส่วนลดจำนวนเงิน

## ต้องตั้งค่าเพิ่ม

- ตัวแปรใน `.env.example` ให้ครบ (`DB_*` บังคับ, `MAIL_*` ไม่ตั้งก็สั่งซื้อได้ แต่จะข้ามการส่งเมลและ log ไว้)
- auth middleware ที่ตั้ง `req.user.id` ก่อน router นี้ และ `express.json()` เหมือนเดิม
- Node 18+ (ใช้ `fetch` กับ `AbortSignal.timeout` ในตัว) — **ถอด `node-fetch` ออกได้** เดิมมันถูก `require` ใหม่ทุก request กลางฟังก์ชัน
- ไม่มี dependency ใหม่ ไม่ต้อง migrate schema

## เสนอเพิ่ม (ยังไม่ได้ทำ)

- **idempotency key** บน `POST /orders` — ตอนนี้ลูกค้ากดปุ่มสั่งซื้อสองครั้งได้สองออเดอร์
- **เงื่อนไขคูปองจริง** — วันหมดอายุ, จำกัดจำนวนครั้ง, ยอดขั้นต่ำ ตาราง `coupons` ตอนนี้มีแค่ `code/type/value` ผมไม่เดาคอลัมน์ที่ยังไม่มี
- **ตัดสต็อก** — ตอนนี้สั่งได้แม้ของหมด
- **index** บน `orders.user_id` และ `order_items.order_id` ถ้ายังไม่มี
- rate limit บน endpoint สร้างออเดอร์
- เปลี่ยน `console.*` เป็น logger ของโปรเจกต์ (pino/winston) พร้อม request id
